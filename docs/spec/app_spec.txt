  <overview>
    Extend the existing Tiger English platform from "lessons + flashcards + dashboard" into a full
    AI-assisted English learning system that guides a learner from A0 (absolute beginner) through
    C1 (advanced independent user). The work is additive on top of an already-deployed React 19 +
    FastAPI + Supabase codebase. The platform should feel like a guided personal tutor combining
    CEFR-grounded structured progression, AI conversation missions, multi-skill scoring, an adaptive
    spaced-repetition review system, level exit assessments, and a teacher/school SaaS layer.
    Source plan: `docs/ai-assisted-english-learning-path.md`. The current state ships unit-1 and
    unit-2 content with a five-section structure (overview/grammar/vocabulary/dialogues/activities),
    a progress event log + projection tables, multi-locale UI (en/vi/th/zh-CN), and a flashcard
    review path. Do not rebuild any of that — extend it.
  </overview>

  <product_vision>
    The platform must answer three questions clearly for every learner:
    1. What can this learner do in English right now?  → surfaced via /skills + cefr_estimate badge
    2. What exactly is holding them back?              → recurring-errors panel + per-skill weak areas
    3. What should they practice next?                 → daily review queue + recommended drills + AI Tutor practice mode

    The learning model is: Learn → Practice → Use → Get Feedback → Review → Re-test → Progress.

    For teachers, the deep-dive shows ability + risk areas + recommended intervention.
    For schools, org-level reports show class progress, seat usage, and engagement metrics —
    enough to justify a SaaS purchase.
  </product_vision>

  <module_lesson_structure>
    The current codebase has a flat `units` structure where each unit has 5 sections
    (overview/grammar/vocabulary/dialogues/activities). To support the full CEFR path, introduce
    a Module → Lesson hierarchy that the current Unit structure becomes a special case of.

    <hierarchy>
      Level (CEFR band, e.g. A1)
        Module (theme group, e.g. "Daily Life and Routines")
          Lesson (single learning unit, ~20-30 min)
            Section (overview / grammar / vocabulary / dialogues / activities — unchanged)
              Block (heading / text / examples / vocab-list / dialogue / exercise / [new types])
    </hierarchy>

    <migration_strategy>
      - Existing `units.ts` data → seed into new `units` table (one row per existing unit)
      - Add `modules` table; create one default module per existing unit during backfill

    <ai_tutor_modes>
      - **Explain mode**: learner types a question; AI returns level-appropriate explanation. Surfaced via "Ask Tutor" panel reachable from any section page.
      - **Practice mode**: AI generates N drill items targeting a specific grammar/vocabulary item (uses level + topic from calling context).
      - **Conversation mode**: real-time roleplay against a scenario (see <ai_conversation_missions>).
      - **Correction mode**: learner submits sentence; AI returns the canonical 4-block correction (see <ai_correction_format>).
      - **Pronunciation Coach**: minimal-pair drills, target-sound feedback. Records learner audio (browser MediaRecorder), transcribes server-side, returns scoring per phoneme. Voice-mode-gated.
      - **Writing Coach**: learner submits text; AI returns CEFR-level feedback (vocab range/accuracy, grammar range/accuracy, organization, task completion), inline suggestions, rewritten exemplar.
      - **Review Coach**: looks at learner's recent error history (`user_activity_log` + `review_items`) and generates a targeted review session.

      All AI feedback follows the principles:
      - Level-appropriate (no C1 grammar to A1 learners)
      - Actionable (tell learner exactly what to improve)
      - Encouraging but honest (no artificially high/low scores)
      - Skill-specific (separate vocab, grammar, pronunciation, fluency, comprehension, task)
      - Evidence-based (show examples from learner's own answer)

      All AI calls use prompt caching keyed on the system prompt + scenario context (see <ai_implementation_details>).
    </ai_tutor_modes>

    <ai_correction_format>
      Canonical correction format the AI must produce when in Correction mode or when correcting
      a sentence inside Conversation/Writing Coach. Renders as a structured `AiFeedbackPanel`
      component on the frontend.

      ```
      Your sentence:
      I go to market yesterday.

      Better sentence:
      I went to the market yesterday.

      Why:
      Use past simple for a finished action in the past. "Go" becomes "went."

      Try again:
      I ___ to the market yesterday.
      ```

      Backend response shape:
      {
        "original": "I go to market yesterday.",
        "corrected": "I went to the market yesterday.",
        "explanation": "Use past simple for a finished action in the past. 'Go' becomes 'went.'",
        "explanation_l1": "<translated to learner's native_language if not 'en'>",
        "try_again_prompt": "I ___ to the market yesterday.",
        "try_again_answer": "went"
      }

      Explanation length scales with level: A0-A1 ≤30 words; A2-B1 ≤60 words; B1+-C1 ≤120 words.
    </ai_correction_format>

    <multi_skill_scoring>
      11 skill categories (per source plan section 13):
      1. vocabulary_range          — Does the learner know enough words for the task?
      2. vocabulary_accuracy       — Are words used correctly?
      3. grammar_accuracy          — Are structures correct enough for the level?
      4. grammar_range             — Does the learner use varied structures?
      5. pronunciation             — Are sounds, stress, rhythm understandable?
      6. fluency                   — Can the learner continue without too many pauses?
      7. listening_comprehension   — Did the learner understand the input?
      8. reading_comprehension     — Did the learner understand the text?
      9. writing_organization      — Are ideas connected clearly?
      10. task_completion          — Did the learner accomplish the communicative goal?
      11. interaction              — Can the learner respond, ask, clarify, continue?

      0–5 rubric per skill:
      0 = no evidence (no answer or unrelated)
      1 = very limited (isolated words only)
      2 = emerging (basic meaning with many errors)
      3 = functional (task completed with some errors but understandable)
      4 = strong (clear, mostly accurate, minor errors)
      5 = excellent for level (natural, accurate, flexible, complete)

      Scoring is **level-relative**: the same answer might score 4/5 at A1 and 2/5 at B2.
      The AI scoring prompt always includes the target CEFR level so scoring matches.

      Storage: `skill_scores` table per (user_id, skill); EWMA-smoothed across last 30 attempts
      (alpha = 2/(N+1) where N is min(sample_size, 30)). Aggregated `cefr_estimate` recomputed
      nightly via Supabase Edge Function or pg_cron task.

      Surfaced on:
      - Dashboard YourProgressCard: "Skill breakdown" mini-row (11 mini-bars)
      - /u/:username/skills page: full grid + history graphs + per-skill recent errors + recommended drills
      - Profile cefr_estimate badge throughout the app
    </multi_skill_scoring>

    <conversation_scoring_criteria>

      EWMA). Used for the mission results screen and for teacher visibility.

      Per the source plan section 13.4:
      1. task_success           — Did the learner complete the mission?
      2. comprehension          — Did they understand the AI's questions?
      3. response_relevance     — Did they answer the question asked?
      4. language_control       — Was grammar and vocabulary appropriate for the level?
      5. repair_ability         — Could they ask for clarification or correct themselves?

    <adaptive_review_system>
      `review_items` table: per-user queue of words, phrases, grammar patterns, pronunciation pairs, common errors, personal sentences.

      Each item has `next_review_at`, `ease_factor` (default 2.5), `interval_days` (integer, capped at 30), `streak_correct`. Modified SM-2 algorithm:
      - On answer: difficult → 1d; correct-but-slow → 3d; correct-confident → 7d; mastered streak ≥4 → 14d, then 30d
      - Incorrect → reset interval to 0 (review same session) + 1d
      - Ease factor adjusts: +0.1 on correct-confident, -0.15 on incorrect, -0.05 on difficult; clamped [1.3, 2.5]

      Items added automatically from:
      - Wrong multiple-choice or fill-in-blank answers (existing `exercise_attempts.is_correct = false`)
      - Hesitations during AI conversation (low confidence flag from AI)
      - Mispronounced words (pronunciation coach feedback)
      - Words the learner asked the AI to translate
      - Grammar mistakes in writing-coach feedback
      - Teacher-assigned vocabulary (via `assigned_lessons`)

      Daily review queue at /u/:username/review pulls due items and runs them through quick drill
      formats per item_type. Review answers feed back into `skill_scores`.

      Dashboard widget: "Today's review: N due" badge.
    </adaptive_review_system>

      Override available via env: `AI_DEFAULT_MODEL` and per-endpoint `AI_MODEL_<ENDPOINT>` variables.
    </model_selection>

    <prompt_caching_strategy>
      Use Anthropic SDK's `cache_control: { type: 'ephemeral' }` on:
      - System prompt block (always cached)
      - Scenario context block (cached when scenario_id is in the request)
      - Lesson context block (cached when unit_slug + section_key in the request)

      Target ≥80% cache hit rate within a 5-minute window. Log cache_creation_input_tokens and
      cache_read_input_tokens to `ai_usage_log` per call. Alert when 24h cache_hit_rate drops below 60%.

      Cache key construction for conversation turns:
      [system_prompt] + [scenario_json] + [target_vocab_grammar] + [conversation_history]
      The first three are cached; conversation_history is the dynamic tail.
    </prompt_caching_strategy>

    <streaming_protocol>
      All streaming endpoints emit SSE events of these types:

      event: metadata
      data: { "session_id": "...", "model": "claude-sonnet-4-6", "scenario_id": "..." }

      event: token
      data: { "content": "partial text chunk" }

      event: done
      data: { "total_tokens": 1234, "stop_reason": "end_turn", "cache_hit_rate": 0.87 }

      event: error
      data: { "code": "rate_limit_exceeded" | "anthropic_unavailable" | "invalid_request", "message": "..." }

      Frontend handling:
      - EventSource with credentials; AbortController to allow stop-generation
      - Render partial tokens as they arrive (character-by-character reveal or accumulated text)
      - On `error`, show toast "Tutor disconnected — retrying" and reconnect with exponential backoff (max 3 attempts)
      - On `done`, finalize the message and update target-vocab side panel
    </streaming_protocol>

    <rate_limits>
      Per-user, per-minute limits enforced via `slowapi` middleware (or in-process token bucket if slowapi unavailable):
      - /me/ai-tutor/*           → 30/min
      - /me/conversations/*/turn → 60/min (allows full conversation pace)
      - /me/conversations/*/end  → 5/min  (scoring is expensive)
      - /me/ai-tutor/writing-coach → 10/min
      - /me/assessments/*        → 5/min

      Org-tier overrides: pro/enterprise plans get 3x the per-user limits.
      On limit breach: 429 response with `Retry-After` header; UI shows toast "Slow down — try again in N seconds".
    </rate_limits>

    <fallback_behavior>
      - If `ANTHROPIC_API_KEY` missing at boot: backend boots but all AI endpoints return 503 with body `{ "code": "ai_disabled", "message": "AI tutor is temporarily unavailable." }`. `/api/v1/health` returns `{ "ai_tutor_enabled": false }` so the frontend can hide AI surfaces.
      - If Anthropic returns 5xx: retry once with exponential backoff (200ms, then 800ms); if still failing, return 502 with `{ "code": "anthropic_unavailable" }`. UI shows "Tutor is having trouble — please try again."
      - If learner closes the SSE connection mid-stream: backend cancels the Anthropic stream, writes a partial turn to `ai_conversation_turns` with `partial = true`, charges no scoring side-effect.
      - If audio upload fails (voice mode): fall back to text-only turn; show toast "Couldn't upload audio — please type your reply."
    </fallback_behavior>

    <system_prompt_templates>
      Stored in `backend/app/services/ai_prompts/`. Each is a Python module with a single
      `build_system_prompt(level: CefrLevel, **kwargs) -> str` function that includes
      cache-friendly static prefix + dynamic tail.

      Files to create:
      - explain_prompt.py        — Tutor explanation; includes level-appropriate complexity caps
      - correct_prompt.py        — Returns the canonical 4-block format JSON
      - practice_prompt.py       — Generates N drill items in JSON
      - writing_coach_prompt.py  — Returns scored breakdown + inline annotations
      - conversation_prompt.py   — Builds scenario context, target vocab/grammar, scoring rubric
      - score_session_prompt.py  — Scores a finished conversation transcript across 6 criteria
      - review_coach_prompt.py   — Generates a personalized review session from recent errors
      - recommended_action_prompt.py — One-line teacher recommendation

      Common prefix all prompts share (cached):
      ```
      You are a CEFR-grounded English tutor. The learner is at level {level}.
      Your responses must be level-appropriate: do not use vocabulary or grammar significantly
      above {level}. Respond in English; if the learner asks, you may briefly translate to {l1}.
      Feedback principles: actionable, encouraging-but-honest, skill-specific, evidence-based.
      ```

      Conversation prompt adds:
      ```
      Scenario: {scenario_title}
      Your role: {ai_role}
      Learner's role: {learner_role}
      Success criteria the learner must achieve: {success_criteria}
      Target vocabulary the learner should try to use: {target_vocabulary}
      Target grammar: {target_grammar}
      Adapt: if the learner says only one word, ask for a full sentence. If they forget polite
      forms, gently prompt them. On success, add a small challenge.
      Stay in character as {ai_role}. Do not break the fourth wall unless the learner explicitly
      asks for tutor mode.
      ```
    </system_prompt_templates>

              AND c.teacher_user_id = auth.uid()
          )
        );

  <key_interactions>
    <ai_conversation_flow>
      Happy path:
      1. Learner is on /lessons/unit-1/activities (food-ordering lesson)
      2. AiMissionBlock renders "Try this conversation: Order a coffee — A1"
      3. Click "Start mission" → POST /me/conversations/start with scenario_id → response includes session_id + opening_line
      4. Navigate to /u/:username/conversations/order-coffee-a1/:sessionId
      5. UI shows tutor opening line ("Hello! What can I get for you today?") rendered as a tutor bubble; target vocab side panel shows "coffee", "tea", "please", "thank you", "small", "large", "anything else" all in gray ("to use")
      6. Learner types "Can I have a coffee, please?" and presses Enter (or Cmd+Enter)
      7. Frontend POSTs to /me/conversations/:session_id/turn with content; opens SSE stream
      8. SSE emits: metadata → token chunks (rendered character-by-character) → done
      9. Side panel updates: "coffee" → green check, "please" → green check, "Can I have" grammar pattern → green check
      10. Tutor responds: "Small or large?"
      11. Learner: "Small, please."
      12. ... continues through 4-6 turns until success criteria met
      13. Learner clicks "End mission"
      14. Confirm modal: "End now? You haven't done step 5 (anything else)." Allow override.
      15. POST /me/conversations/:session_id/end → backend scores via Claude (sonnet-4-6) → updates skill_scores + auto-creates review items for misses
      16. Results screen: 6-criteria scores grid + missed criteria highlighted + "Try again" / "Next mission" / "Back to lesson" CTAs

      Edge cases:
      - Network drop mid-stream: SSE reconnect with exponential backoff (200ms, 800ms, 3200ms); if still failing, show "Tutor disconnected — please retry your turn" toast and roll back the partial turn to "draft"
      - Learner closes tab mid-session: turn marked partial=true; session status='active'; learner sees "Continue mission" CTA on /conversations next visit
      - Rate limit hit: 429 with Retry-After; UI shows toast "Slow down — try again in N seconds"; input disabled until expiry
      - Anthropic 5xx: 502 returned; UI shows "Tutor is having trouble — please try again"; "Retry" button on the failed turn
      - Voice mode disabled but learner clicks mic: button is hidden when feature flag off
      - Learner uses inappropriate language: tutor system prompt instructs gentle redirection in-character; no system-level moderation modal needed
    </ai_conversation_flow>

    <review_flow>

      - User leaves mid-session: items already answered are persisted; remaining items return on next session
      - User answers item correctly that they got wrong last time: streak_correct increments; ease_factor +0.1

  <content_authoring_guidelines>
    Per source plan section 20. The agent applies these when generating new lesson content
    (and when adapting AI tutor responses to level).

    <a0_a1>
      - Use short sentences (max 10 words for A0; max 15 for A1)
      - Use pictures and audio heavily (every vocab item has an image + TTS clip)
      - Avoid long grammar explanations (max 80 words per explanation)
      - Translate vocabulary into vi/th/zh always; translate sample sentences when complexity warrants
      - Prioritize survival communication (greetings, ordering, asking basic info)
      - Give many examples (4-6 per grammar point)
      - Accept imperfect but understandable output (scoring threshold: comprehensible = passing)
    </a0_a1>

    <a1_a2>
      - Use predictable daily situations (routines, shopping, health, travel)
      - Increase short dialogues (4-8 turns); always include TTS clip
      - Start short reading texts (40-80 words)
      - Teach sentence patterns clearly (one pattern per lesson)
      - Use controlled roleplays (success criteria explicit)
      - Encourage short written output (5-10 sentences)
      - Translate explanations when learner is &lt;A2 (set per profile.cefr_estimate)
    </a1_a2>

    <a2_b1>
      - Add storytelling, opinions, reasons, plans
      - Use follow-up questions (every conversation prompt should have a follow-up)
      - Teach connectors and paragraph structure (because, however, for example, finally)
      - Increase AI conversation length (5-7 minutes; ~6-10 turns)
      - Give feedback on tense consistency (past simple vs present perfect is the canonical contrast)
      - Reading texts: 100-180 words
      - Writing tasks: 80-150 words
    </a2_b1>

    <b1_b2>
      - Add work, study, society, technology, abstract topics
      - Teach formality and tone (informal ↔ neutral ↔ formal)
      - Use longer speaking tasks (10-15 minutes)
      - Require examples and explanations (no opinion without support)
      - Introduce debate and problem-solving
      - Reading texts: 200-400 words
      - Writing tasks: 180-300 words
    </b1_b2>

    <b2_c1>
      - Focus on nuance, register, argument, persuasion, precision
      - Use authentic-style texts (news articles, opinion pieces, professional emails)
      - Require structured long-form speaking (15-20 minutes) and writing (300-600 words)
      - Teach editing and reformulation (revise the same idea for casual/formal/diplomatic)
      - Challenge the learner with counterarguments and ambiguity
      - No translation in feedback — respond in English at level
    </b2_c1>
  </content_authoring_guidelines>
