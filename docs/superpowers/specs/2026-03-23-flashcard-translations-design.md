# Flashcard Translations Design

**Date:** 2026-03-23
**Branch:** main (new feature branch at implementation time)
**Status:** Draft

## Overview

Add per-language native translations for flashcard sets so Thai, Chinese, and Vietnamese users all see the same set (e.g. "Fruit") with their own native text. Translations are generated offline via a dev-time script using the Claude API (Haiku), reviewed by a human, then committed as a SQL migration.

## Goals

- Thai, Chinese, Vietnamese users see native text on the front of every card
- User's native language is captured at registration and changeable in settings
- Translation generation is automated, human-reviewed, and idempotent
- `native_audio_url` is stored per-language alongside `native_text`
- Schema is safe to roll out incrementally without a flag day

## Non-Goals

- Real-time / on-demand translation (future option)
- Languages beyond `th`, `zh`, `vi` in this iteration
- Enforcing `profiles.native_language NOT NULL` in this feature (follow-up migration after onboarding coverage is confirmed)

## Schema Changes

### New table: `languages`

A reference table for supported language codes. Adding a new language is a single `INSERT` — no constraint rewrites needed on `flashcard_translations` or `profiles`.

```sql
CREATE TABLE languages (
  code  text PRIMARY KEY CHECK (code = lower(trim(code)) AND length(trim(code)) > 0),
  name  text NOT NULL
);

INSERT INTO languages (code, name) VALUES
  ('th', 'Thai'),
  ('zh', 'Chinese'),
  ('vi', 'Vietnamese');

GRANT SELECT ON languages TO anon, authenticated;
```

No RLS needed — language list is fully public.

### New table: `flashcard_translations`

```sql
CREATE TABLE flashcard_translations (
  flashcard_id      uuid NOT NULL REFERENCES flashcards(id) ON DELETE CASCADE,
  language_code     text NOT NULL REFERENCES languages(code),
  native_text       text NOT NULL CHECK (length(trim(native_text)) > 0),
  native_audio_url  text,
  source            text NOT NULL DEFAULT 'ai'
                    CHECK (source IN ('ai', 'human', 'import')),
  is_reviewed       bool NOT NULL DEFAULT false,
  updated_by        uuid REFERENCES profiles(id) ON DELETE SET NULL,
  created_at        timestamptz NOT NULL DEFAULT now(),
  updated_at        timestamptz NOT NULL DEFAULT now(),
  PRIMARY KEY (flashcard_id, language_code)
);

-- Primary access pattern: fetch all translations for a card, then filter in app code.
-- Composite index is more selective than a single language_code index.
CREATE INDEX idx_flashcard_translations_lookup
  ON flashcard_translations (flashcard_id, language_code);

-- extensions.moddatetime is already enabled in 20260319000001_initial_schema.sql
CREATE TRIGGER handle_flashcard_translations_updated_at
  BEFORE UPDATE ON flashcard_translations
  FOR EACH ROW EXECUTE PROCEDURE extensions.moddatetime(updated_at);

ALTER TABLE flashcard_translations ENABLE ROW LEVEL SECURITY;
```

**`source`** records translation provenance: `'ai'` (generated by Claude), `'human'` (manually written or edited), `'import'` (bulk-imported from an external dataset).

**`updated_by`** records who last edited a translation row — nullable (null for AI-generated rows before any human review).

**`is_reviewed`** marks translations verified by a human. The mapper only surfaces reviewed translations to users — unreviewed AI drafts are stored but not shown.

**Note on multiple drafts:** The current PK `(flashcard_id, language_code)` enforces one row per card+language. If a future workflow needs multiple drafts alongside one published translation, the PK would change and a partial unique index `ON (flashcard_id, language_code) WHERE is_reviewed = true` would enforce the one-published constraint. Out of scope for this iteration.

### RLS Policies and Grants

`flashcard_translations` rows are readable under the same conditions as their parent `flashcards` row.

```sql
CREATE POLICY "flashcard_translations_select" ON flashcard_translations
  FOR SELECT USING (
    EXISTS (
      SELECT 1 FROM flashcards f
      JOIN flashcard_sets s ON s.id = f.set_id
      WHERE f.id = flashcard_translations.flashcard_id
        AND (
          s.created_by IS NULL
          OR s.is_public = true
          OR s.created_by = auth.uid()
        )
    )
  );

GRANT SELECT ON flashcard_translations TO anon, authenticated;
```

### `profiles` — add `native_language` (nullable first)

References the `languages` table — valid codes are enforced by FK, no separate CHECK constraint needed.

```sql
ALTER TABLE profiles
  ADD COLUMN native_language text REFERENCES languages(code);
  -- nullable; null = language not yet set
```

`null` is valid during the transition period. A follow-up migration enforces `NOT NULL` after onboarding guarantees every row has a value:

```sql
DO $$
DECLARE unset_count int;
BEGIN
  SELECT COUNT(*) INTO unset_count FROM profiles WHERE native_language IS NULL;
  IF unset_count > 0 THEN
    RAISE EXCEPTION '% profile(s) still have null native_language — backfill before running this migration', unset_count;
  END IF;
END $$;

ALTER TABLE profiles ALTER COLUMN native_language SET NOT NULL;
```

Adding a new supported language: `INSERT INTO languages (code, name) VALUES ('new', 'New Language')`. No constraint rewrites. The backend `SUPPORTED_LANGUAGES` constant must also be updated.

### `flashcards` — column removals

`native_audio_url` is dropped in this migration (no data — added in schema v2 but never populated).

`native_text` is **kept**. It will be dropped in a follow-up migration after app reads are verified against `flashcard_translations`.

> **Note:** `20260319000004_seed_curated_sets.sql` uses the old column name `native_word` (predates the v2 rename). That file does not need changing — it runs before the rename migration. Re-running it in isolation after v2 would fail. Known pre-existing state.

```sql
ALTER TABLE flashcards DROP COLUMN native_audio_url;
```

### Migration order (single migration file)

1. Create `languages` table + seed rows + grant
2. Create `flashcard_translations` table + index + trigger + RLS + grant
3. Drop `flashcards.native_audio_url`
4. Add `profiles.native_language` (nullable FK)
5. Backfill existing curated sets into `flashcard_translations`:

```sql
-- These UUIDs are fixed constants defined in 20260319000004_seed_curated_sets.sql.
-- They are stable by design. Update this migration if new curated sets are added.
DO $$
DECLARE unexpected_count int;
BEGIN
  SELECT COUNT(*) INTO unexpected_count
  FROM flashcard_sets
  WHERE created_by IS NULL
    AND id NOT IN (
      '00000000-0000-0000-0000-000000000001',
      '00000000-0000-0000-0000-000000000002'
    );
  IF unexpected_count > 0 THEN
    RAISE EXCEPTION 'Unexpected curated sets found — update migration before proceeding';
  END IF;
END $$;

INSERT INTO flashcard_translations
  (flashcard_id, language_code, native_text, source, is_reviewed)
SELECT
  f.id,
  CASE s.id
    WHEN '00000000-0000-0000-0000-000000000001' THEN 'th'
    WHEN '00000000-0000-0000-0000-000000000002' THEN 'zh'
  END,
  f.native_text,
  'human',
  true
FROM flashcards f
JOIN flashcard_sets s ON s.id = f.set_id
WHERE s.created_by IS NULL
  AND s.id IN (
    '00000000-0000-0000-0000-000000000001',
    '00000000-0000-0000-0000-000000000002'
  )
ON CONFLICT (flashcard_id, language_code) DO NOTHING;
```

## Translation Generation Workflow

### Step 1 — Generate translations (`scripts/generate-translations.ts`)

Reads all flashcards with no `flashcard_translations` row (with `is_reviewed = true`) for a target language. Calls the Claude API (Haiku) in batches.

```typescript
import Anthropic from '@anthropic-ai/sdk';

const client = new Anthropic({
  apiKey: process.env.ANTHROPIC_API_KEY, // standard Anthropic API key (sk-ant-...)
  // Note: ANTHROPIC_CODE_OAUTH_TOKEN is a Claude Code OAuth credential
  // and is not accepted by the SDK's apiKey parameter.
});
```

Prompt (per language, per batch):
```
Translate the following English words/phrases to Thai.
Return ONLY a JSON array with this exact shape:
[{ "id": "<flashcard_id>", "native_text": "<translation>" }, ...]
If you are not confident about a translation, prefix native_text with "?".
Do not add explanations, romanisation, or alternatives.

Cards:
[{ "id": "...", "english_text": "Apple", "category": "fruit" }, ...]
```

Output: `src/data/translations/<language_code>_review.csv`

```
flashcard_id,english_text,category,native_text,flagged
<uuid>,Apple,fruit,แอปเปิ้ล,false
<uuid>,Dragon fruit,fruit,แก้วมังกร,false
<uuid>,Guava,fruit,ฝรั่ง,true
```

`flagged=true` rows (Claude prefixed with "?") are sorted to the top for fast human review. A human edits `native_text` and clears the flag before step 2.

### Step 2 — Generate migration (`scripts/generate-translations-migration.ts`)

Reads reviewed CSVs. Fails if any row still has `flagged=true`. Emits:

`supabase/migrations/<timestamp>_translations_<lang>.sql`

```sql
INSERT INTO flashcard_translations
  (flashcard_id, language_code, native_text, source, is_reviewed)
VALUES (...)
ON CONFLICT (flashcard_id, language_code) DO UPDATE
  SET native_text  = EXCLUDED.native_text,
      source       = EXCLUDED.source,
      is_reviewed  = true,
      updated_at   = now();
```

`DO UPDATE` so re-running after editing the review CSV updates the stored translation.

## Backend Changes

### Supported languages — centralised constant

```python
# backend/app/core/languages.py
SUPPORTED_LANGUAGES = {'th', 'zh', 'vi'}

def validate_native_language(value: str | None) -> str | None:
    if value is None:
        return None
    if value not in SUPPORTED_LANGUAGES:
        raise ValueError(f"Unsupported language code: {value!r}")
    return value
```

Called from both the registration handler and `PATCH /profile`. Adding a new language: insert into `languages` table + update this set. The FK on `profiles.native_language` and `flashcard_translations.language_code` both enforce against the `languages` table, so the DB and backend stay in sync automatically.

### `POST /auth/register` — include `native_language`

`native_language` is validated then written via `UPDATE profiles SET native_language = :value WHERE id = :user_id` immediately after `admin.create_user` returns. The DB trigger creates the `profiles` row; FastAPI updates it in the same request. If the user submits without selecting a language, `native_language` is omitted and stored as `null`. It is never silently defaulted.

### `PATCH /profile` — update `native_language`

New endpoint. Validates the caller's Supabase JWT (`Authorization: Bearer <token>`); the user ID is extracted from the verified token and never accepted from the request body. Validates `native_language` against `SUPPORTED_LANGUAGES`. Returns 400 for unknown codes. Returns the updated profile on success.

### Card queries — frontend Supabase client (not FastAPI)

Card fetching uses the Supabase JS client directly from the frontend (no FastAPI endpoint for cards). The query fetches all `flashcard_translations` rows for each card without a language filter — filtering in app code preserves the LEFT JOIN behaviour and ensures cards without translations are not silently dropped.

> **PostgREST filter behaviour:** Adding `.eq('flashcard_translations.language_code', languageCode)` to a PostgREST embedded resource query converts the implicit LEFT JOIN to an INNER JOIN — cards with no translation row are excluded entirely. To keep unmatched cards visible (showing a placeholder), fetch all translation rows and filter in the mapper.

```typescript
const { data, error } = await supabase
  .from('flashcards')
  .select(`
    id, set_id, english_text, part_of_speech, level, category,
    example_sentence, english_audio_url, image_url,
    notes, is_phrase, sort_order,
    flashcard_translations(native_text, native_audio_url, language_code, is_reviewed)
  `)
  .eq('set_id', setId)
  .order('sort_order', { ascending: true });
  // No filter on flashcard_translations.language_code — see note above
```

## Frontend Changes

### `FlashcardCard` type

`nativeText: string | null`, `nativeAudioUrl: string | null` — both null when no reviewed translation exists for the user's language.

The `mapCard` function and `CardRow` type require a full rewrite. `native_text` is no longer selected directly from `flashcards`; it comes from the embedded `flashcard_translations` array. The mapper finds the reviewed translation for the requested language:

```typescript
type TranslationRow = {
  native_text: string;
  native_audio_url: string | null;
  language_code: string;
  is_reviewed: boolean;
};

type CardRow = {
  // ... existing fields, minus native_text and native_audio_url ...
  flashcard_translations: TranslationRow[];
};

export function mapCard(row: CardRow, languageCode: string): FlashcardCard {
  const translation = row.flashcard_translations
    .find(t => t.language_code === languageCode && t.is_reviewed) ?? null;
  return {
    // ... existing fields ...
    nativeText: translation?.native_text ?? null,
    nativeAudioUrl: translation?.native_audio_url ?? null,
  };
}
```

Only reviewed translations are surfaced. An unreviewed AI draft is stored but treated as missing.

### `useFlashcards(setId, languageCode)` — guarded fetch

Fetches only when **both** `setId` and `languageCode` are non-null. Passes `languageCode` to `mapCard`.

### Language resolution (client, read-only — nothing silently persisted)

1. `profile.native_language` from Zustand — authoritative once set
2. If null (transition period): onboarding-selected value held in local component state
3. If neither: language selector shown, card fetch blocked until user selects

### Registration — language selector

- Browser locale normalised (e.g. `"th-TH"` → `"th"`)
- If locale matches `SUPPORTED_LANGUAGES`: selector pre-filled
- If unmatched: selector empty with placeholder "Choose your native language" — no default applied
- Submitted in the same registration API call

### Settings — immediate effect on language change

```typescript
// After successful PATCH /profile
useUserStore.getState().setNativeLanguage(newCode);
// next useFlashcards call picks up new languageCode — no reload needed
```

### `Flashcard.tsx` — untranslated card state

When `nativeText` is null, the front of the card shows a "Translation coming soon" placeholder. The `aria-label` must null-guard `nativeText` to avoid rendering the string `"null"` for screen readers. Showing `englishText` on the native-language side would invert the learning direction. Untranslated cards are visually distinct and non-interactive.

### i18n locale files

Language selector labels and placeholder text are added to `src/locales/en/en.json` and `src/locales/th/th.json`.

## Future Considerations (out of scope)

**Organisation-level translations** — add `organization_id uuid REFERENCES organizations(id)` to `flashcard_translations`. Enables custom vocabulary per school or enterprise customer, with org translations overriding defaults.

**User-contributed translations** — add `created_by uuid REFERENCES profiles(id)`. Enables community corrections, a voting system, and crowdsourced improvements.

**Multiple translations per card** — some languages need contextual variants (formal/informal, regional dialects). Would require changing the PK and adding a partial unique index `ON (flashcard_id, language_code) WHERE is_reviewed = true`.
